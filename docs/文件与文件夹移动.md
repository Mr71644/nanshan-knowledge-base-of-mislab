## 第一节 文件与文件夹移动的业务流程分析

### 一、文件树移动功能

#### 1.移动功能说明

文件与文件夹移动功能用于将文件树中的一个节点移动到另一个文件夹下，或移动到根目录下。该功能只改变节点在系统目录树中的父级关系和显示顺序，不改变普通文件在 MinIO 中已经生成的对象路径，因此普通文件移动后，历史 URL 仍然可以继续使用。

当前系统支持移动的节点类型如下：

| 节点状态 itemStatus | 节点类型 | 对应数据表 | 父级字段 |
| --- | --- | --- | --- |
| 1 | 文档 | text | folder_id |
| 2 | 文件夹 | folders | parent_id |
| 3 | Excel | excel | folder_id |
| 4 | 普通文件 | file | folder_id |

移动操作完成后，需要更新对应数据表中的父级字段、sort_order 字段和 update_time 字段。

#### 2.移动功能接口

移动节点的后端接口为：

```http
PUT /home/move
Content-Type: application/json
Authorization: Bearer <token>
```

请求参数包括：

| 参数名称 | 参数类型 | 是否必填 | 参数说明 |
| --- | --- | --- | --- |
| itemId | Integer | 是 | 被移动节点的业务 ID。 |
| itemStatus | Integer | 是 | 被移动节点类型，取值范围为 1-4。 |
| targetFolderId | Integer/null | 否 | 目标父文件夹 ID，为 null 时表示移动到根目录。 |

请求示例如下：

```json
{
  "itemId": 101,
  "itemStatus": 4,
  "targetFolderId": 12
}
```

处理成功时，系统返回：

```json
{
  "code": 200,
  "message": "success",
  "data": null
}
```

#### 3.移动功能的代码位置

文件与文件夹移动功能在后端系统中的代码位置如下：

| 层级 | 文件 | 作用 |
| --- | --- | --- |
| Controller | src/main/java/wiki/record/application/controller/HomeController.java | 提供 PUT /home/move 接口，接收 HomeMoveDTO 参数。 |
| DTO | src/main/java/wiki/record/application/pojo/dto/home/HomeMoveDTO.java | 对 itemId、itemStatus 等请求参数进行校验。 |
| Service 接口 | src/main/java/wiki/record/application/service/HomeService.java | 定义 moveItem(itemId, itemStatus, targetFolderId) 方法。 |
| Service 实现 | src/main/java/wiki/record/application/service/impl/HomeServiceImpl.java | 完成节点存在性校验、权限校验、防循环校验、排序号分配和父级更新。 |
| 排序服务 | src/main/java/wiki/record/application/service/SortOrderService.java | 计算目标父级下的新 sort_order。 |
| 权限工具 | src/main/java/wiki/record/application/util/FolderPermissionUtil.java | 判断当前用户是否拥有文件夹 VIEW、EDIT 权限，以及是否为超级管理员。 |
| 全局异常 | src/main/java/wiki/record/application/config/expcetion/GlobalExceptionHandler.java | 将参数异常映射为 400，将权限异常映射为 403。 |

### 二、移动节点的业务处理流程

#### 1.普通节点移动

普通节点移动的业务流程：

1. 用户在文件树中选择需要移动的节点，并指定目标文件夹。如果目标文件夹为空，则表示将节点移动到根目录。

2. 前端向后端提交移动请求，提交内容包括 itemId、itemStatus 和 targetFolderId。

3. HomeController 接收请求后，将参数传入 HomeService 的 moveItem 方法。

4. HomeServiceImpl 在事务中处理移动逻辑。若处理过程中发生参数错误、权限不足或数据库更新异常，则本次移动操作整体回滚。

5. 系统先校验 itemId 和 itemStatus。itemId 不能为空，itemStatus 不能为空且必须属于 1-4 范围。

6. 系统根据 itemStatus 查询被移动节点，并取得该节点当前所在的源父级 ID。

7. 系统校验目标文件夹。若 targetFolderId 为空，则表示目标位置为根目录；若 targetFolderId 不为空，则必须在 folders 表中存在未删除的目标文件夹。

8. 系统校验用户对源父级和目标父级的编辑权限。根目录作为源父级或目标父级时，只允许超级管理员操作。

9. 系统调用 SortOrderService.nextSortOrder 方法，计算节点移动到目标父级后的新排序号。

10. 系统按照 itemStatus 更新对应表的父级字段、sort_order 字段和 update_time 字段。

11. 更新成功后，接口返回 success，前端重新加载文件树或局部刷新目标目录。

#### 2.文件夹移动

文件夹移动在普通节点移动流程的基础上，还需要增加防循环校验。

文件夹移动的业务流程：

1. 用户选择需要移动的文件夹，并指定目标文件夹或根目录。

2. 系统根据文件夹 ID 查询 folders 表，确认该文件夹存在且未删除。

3. 系统校验当前用户是否对被移动文件夹本身具有 EDIT 权限。

4. 系统校验当前用户是否对源父级具有 EDIT 权限。

5. 系统校验当前用户是否对目标父级具有 EDIT 权限。若目标父级是根目录，则当前用户必须是超级管理员。

6. 系统判断目标位置是否合法。文件夹不能移动到自身下，也不能移动到自己的任意子文件夹下。

7. 如果目标位置合法，则计算目标父级下的新 sort_order。

8. 系统更新 folders 表中的 parent_id、sort_order 和 update_time。

9. 更新完成后，文件夹及其下级节点在逻辑目录树中整体迁移到目标位置。

特别注意：文件夹移动时必须执行防循环校验。例如目录结构为：

```text
A
└── B
    └── C
```

系统不允许将 A 移动到 B 或 C 下面，否则会造成树形结构循环。

### 三、节点校验与数据更新规则

#### 1.获取源父级

系统通过 getSourceFolderId(itemId, itemStatus) 获取被移动节点的源父级。该方法需要先确认节点存在，并且只查询未删除的数据。

不同节点类型的源父级规则如下：

| 节点类型 | 查询表 | 源父级字段 |
| --- | --- | --- |
| text | text | folder_id |
| folder | folders | parent_id |
| excel | excel | folder_id |
| file | file | folder_id |

若节点不存在，或节点已经进入回收站，则系统抛出 IllegalArgumentException("节点不存在")。

#### 2.校验目标文件夹

目标文件夹校验规则如下：

1. targetFolderId 为 null 时，表示移动到根目录，不需要查询 folders 表。

2. targetFolderId 不为 null 时，系统必须能在 folders 表中查询到未删除的目标文件夹。

3. 如果目标文件夹不存在，则系统抛出 IllegalArgumentException("目标文件夹不存在")。

#### 3.计算新排序号

移动成功后，节点会追加到目标父级同级列表的末尾。

SortOrderService.nextSortOrder(targetFolderId, itemStatus) 需要统计目标父级下所有未删除兄弟节点的最大 sort_order。统计范围不是单一类型，而是跨 folders、text、excel、file 四张表统一计算。

统计字段如下：

| 数据表 | 父级字段 |
| --- | --- |
| folders | parent_id |
| text | folder_id |
| excel | folder_id |
| file | folder_id |

排序号计算规则为：

```text
新 sort_order = 当前最大 sort_order + 1
```

如果目标父级下没有任何兄弟节点，则新 sort_order 为 0。

#### 4.更新目标父级

系统最终通过 updateItemParentAndSortOrder 方法按节点类型更新对应数据表。

更新规则如下：

| itemStatus | 更新内容 |
| --- | --- |
| 1 | 更新 text.folder_id、sort_order、update_time。 |
| 2 | 更新 folders.parent_id、sort_order、update_time。 |
| 3 | 更新 excel.folder_id、sort_order、update_time。 |
| 4 | 更新 file.folder_id、sort_order、update_time。 |

### 四、移动权限判定

#### 1.权限校验原则

文件与文件夹移动属于会改变目录结构的操作，因此需要检查编辑权限。

权限判定原则如下：

1. 移动普通文件、文档或 Excel 时，用户必须对源父级具有 EDIT 权限。

2. 移动普通文件、文档或 Excel 时，用户必须对目标父级具有 EDIT 权限。

3. 移动文件夹时，用户必须对被移动文件夹本身具有 EDIT 权限。

4. 移动文件夹时，用户还必须对源父级和目标父级具有 EDIT 权限。

5. 根目录作为源父级或目标父级时，只允许超级管理员操作。

#### 2.不同移动场景的权限要求

| 移动场景 | 权限要求 |
| --- | --- |
| 文件从文件夹 A 移动到文件夹 B | 对 A 有 EDIT 权限，对 B 有 EDIT 权限。 |
| 文件从根目录移动到文件夹 B | 必须是超级管理员，并对 B 有 EDIT 权限；超级管理员天然满足。 |
| 文件从文件夹 A 移动到根目录 | 必须是超级管理员，并对 A 有 EDIT 权限；超级管理员天然满足。 |
| 文件夹 X 从文件夹 A 移动到文件夹 B | 对 X 有 EDIT 权限，对 A 有 EDIT 权限，对 B 有 EDIT 权限，且 B 不是 X 自身或其子级。 |
| 文件夹 X 从根目录移动到文件夹 B | 必须是超级管理员，同时目标不能是自身或子级。 |
| 文件夹 X 移动到根目录 | 必须是超级管理员，同时目标不能是自身或子级。 |

### 五、异常返回处理

#### 1.参数与业务异常

移动功能中常见的异常返回如下：

| HTTP 状态 | 常见原因 | 后端异常 |
| --- | --- | --- |
| 400 | itemId 为空、itemStatus 为空、itemStatus 不在 1-4、节点不存在、目标文件夹不存在、移动到自身或子文件夹 | IllegalArgumentException 或参数校验异常 |
| 401 | 未登录、token 缺失、token 过期 | 登录拦截器直接返回 |
| 403 | 无源父级编辑权限、无目标父级编辑权限、普通用户操作根目录 | SecurityException |
| 500 | 未预期运行时异常 | RuntimeException |

#### 2.典型失败返回

当用户没有编辑权限时，系统返回：

```json
{
  "code": 403,
  "message": "无编辑权限",
  "data": null
}
```

当用户试图将文件夹移动到自己的子文件夹时，系统返回：

```json
{
  "code": 400,
  "message": "不能移动到自己的子文件夹",
  "data": null
}
```
