# 用户迁移测试 — 可视化调试方案

**阶段：** 开发完成后、正式上线前  
**目标：** 让开发者和测试人员在迁移过程中能实时看到转换状态，逐文档确认成功或排查失败

---

## 一、与正式环境的区别

| | 测试阶段 | 正式上线后 |
|------|----------|------------|
| 迁移日志 | 页面内**可见面板** | 仅 console |
| 逐文档状态 | **实时列表**，绿色通过/红色失败 | localStorage 记录 |
| 失败详情 | **即时展示**错误原因和文档 ID | console.error |
| 触发方式 | 登录后自动，也可**手动触发** | 登录后自动 |
| 重置能力 | 可**清除迁移记录**重新执行 | 不需要 |

---

## 二、测试阶段专用：迁移状态面板

### 2.1 外观

页面右下角显示一个**半透明浮窗**，登录后如果检测到有待迁移文档则自动展开：

```
┌──────────────────────────────────────┐
│  📋 文档格式迁移                    │
│  待迁移: 142 个                      │
│  进度: 38/142 (27%)                  │
│  ████████░░░░░░░░░░░░░░              │
│                                      │
│  ✅ 文档 23: 测试用例1 (1.3x)        │
│  ✅ 文档 40: 老版本兼容 (3.5x)       │
│  ✅ 文档 75: 数据库设计 (6.1x)       │
│  ❌ 文档 42: 转换异常 → 跳过         │
│  ⏳ 正在处理: 文档 50...              │
│                                      │
│  [收起面板] [暂停迁移]              │
└──────────────────────────────────────┘
```

### 2.2 交互

| 操作 | 行为 |
|------|------|
| 点击某文档行 | 展开详情：原始 MD 前 200 字符 + 转换后 JSON 前 200 字符 |
| "收起面板" | 折叠为仅显示进度条的一行 |
| "暂停迁移" | 停止当前批次后的处理 |
| 刷新页面 | 已完成的保留，未完成的重新开始 |
| 迁移全部完成 | 面板自动在 5 秒后淡出消失 |

### 2.3 失败行的详情展开

点击失败的文档行，展开：

```
┌──────────────────────────────────────┐
│  ❌ 文档 42: 转换异常                │
│                                      │
│  错误: Unexpected end of JSON input  │
│  原始 Markdown (前 200 字符):        │
│  # 文档标题\n\n**粗体文字**\n\n...   │
│                                      │
│  [手动重试此文档] [在编辑器中打开]    │
└──────────────────────────────────────┘
```

## 三、实现方案

### 3.1 组件结构

```
src/components/MigrationTestPanel/
  ├── index.jsx           # 主面板组件
  └── index.module.css    # 样式
```

### 3.2 判断逻辑

```js
// 仅在开发/测试环境启用可视化面板
const isTestMode = import.meta.env.VITE_MIGRATION_TEST === 'true'

// 或者直接通过环境变量判断
const isDev = import.meta.env.DEV

// 或者提供一个手动开关
// Home 页按 Ctrl+Shift+M 强制打开面板
```

**建议：** 使用环境变量 `VITE_MIGRATION_TEST=true` 控制。测试时设为 true，正式上线设为 false（或删除变量）即自动回到完全静默模式。

### 3.3 数据流

```
migrationScheduler.js
  │
  ├── onBatchComplete({ batchIndex, totalBatches, success, failed })
  │     └──→ 更新面板进度条
  │
  ├── onDocumentSuccess({ id, title, mdLen, jsonLen, ratio })
  │     └──→ 面板列表追加一条绿色行
  │
  ├── onDocumentFailed({ id, title, reason, mdSnippet })
  │     └──→ 面板列表追加一条红色行（可展开）
  │
  └── onComplete({ total, success, failed, durationMs })
        └──→ 面板显示"完成"，5 秒后自动收起
```

### 3.4 与现有调度器的关系

现有 `migrationScheduler.js` 已经设计了 `onProgress` 和 `onComplete` 回调。测试阶段只需要在 Home 页将这些回调连接到面板组件，而不需要修改调度器本身。

---

## 四、测试检查清单

测试期间逐项验证：

- [ ] 登录后右下角自动出现迁移面板
- [ ] 进度条和计数正确递增
- [ ] 成功文档显示绿色行，含文件 ID、标题、体积比
- [ ] 失败文档显示红色行，可点击展开看错误详情
- [ ] 点击失败行的"在编辑器中打开"跳转到该文档
- [ ] 收起面板后进度条仍可见
- [ ] 迁移全部完成后面板自动消失
- [ ] 刷新页面后已完成的文档不重复出现
- [ ] 关闭面板的环境变量后，迁移完全静默（回归验证）

| 内容 | 耗时 |

| MigrationTestPanel 组件 | 1 小时 |
