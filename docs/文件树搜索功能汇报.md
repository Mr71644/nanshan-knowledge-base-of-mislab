# 文件树搜索功能 — 功能汇报

## 一、功能背景

在知识库的日常使用中，随着文件和文件夹数量增多，用户需要在左侧文件树中快速定位目标文件。此前只能通过手动逐层展开查找，效率较低。本次新增文件树搜索功能，支持按名称实时检索，提升文件定位效率。

---

## 二、功能介绍

在左侧文件树上方新增搜索输入框，支持以下能力：

| 能力 | 说明 |
|---|---|
| 实时搜索 | 输入即筛选，无需点击搜索按钮，逐字响应 |
| 高亮显示 | 匹配到的文件/文件夹名称中，关键词部分用黄色背景标记 |
| 自动展开 | 匹配节点的父级路径自动展开，定位一目了然 |
| 淡化非匹配 | 未匹配的节点降低透明度，保持树结构可见但不干扰视线 |
| 一键清除 | 点击输入框 × 按钮或清空文字，立即恢复完整树 |
| 中英支持 | 大小写不敏感，中文和英文搜索均可正常工作 |

---

## 三、技术方案

### 方案选型

经评估，采用**纯前端过滤**方案，而非调用后端 API 搜索。

| 对比维度 | 前端过滤（已选） | 后端搜索 |
|---|---|---|
| 响应速度 | < 1ms，即时响应 | 50-200ms 网络延迟 |
| 用户体验 | 逐字实时反馈 | 输入后需等待 |
| 开发成本 | 仅改前端 3 个文件 | 前后端均需改动 |
| 搜索范围 | 文件/文件夹名称 | 可扩展到文件内容 |

**选型依据**：

1. **数据规模匹配** — 知识库文件树典型规模为几十到几百个节点，前端遍历在亚毫秒级完成，无性能瓶颈
2. **体验优先** — 搜索的核心体验是"边输入边看到结果"，前端方案无延迟
3. **成本最低** — 不需要新增 API、改后端、处理异步加载状态

### 实现架构

```
用户输入关键词
      ↓
 searchText 状态更新
      ↓
 useMemo 触发 walkFilter 递归遍历
      ↓
 输出两个集合：匹配节点 + 祖先路径
      ↓                ↓
 自动展开路径       高亮匹配文字 / 淡化非匹配项
```

核心是一个递归函数 `walkFilter`，遍历已加载的树数据，按名称进行大小写不敏感匹配，同时记录匹配节点的所有祖先路径，用于自动展开和高亮。

如未来有需要，可考虑：
