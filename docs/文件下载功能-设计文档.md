# 文件统一下载功能 — 前端设计文档

## 一、背景与目标

后端新增了统一下载接口，覆盖文件树中的四类资源：

| status | 资源类型 | 下载结果 |
|--------|----------|----------|
| 1 | 文本/论文 | 无图片时返回 `.md`；包含可离线化图片时返回 `.zip`（含 `文档.md` + `assets/` 图片目录） |
| 2 | 文件夹 | `.zip` 压缩包（递归包含子资源） |
| 3 | 在线 Excel | `.json` 文件 |
| 4 | 普通上传文件 | 原始文件 |

**当前状态：**
- status=4 普通文件仅有预览功能（新窗口打开 URL），无下载功能
- status=1/2/3 没有任何下载入口
- 已有批量选择模式，但只有 "移入回收站" 操作

**目标：**
1. 为所有 4 种资源类型添加 "下载" 菜单项（单个下载）
2. 在批量操作栏中添加 "下载" 按钮（批量下载）

---

## 二、接口信息

### 2.1 单个资源下载

```
GET /document/download/{status}/{id}
Authorization: Bearer <token>
```

- 响应：文件流（blob），非 JSON
- 文件名从 `Content-Disposition` 头中解析

### 2.2 批量资源下载

```
POST /document/download/batch
Authorization: Bearer <token>
Content-Type: application/json

{
  "archiveName": "资料下载",
  "items": [
    { "id": 12, "status": 4 },
    { "id": 3, "status": 1 }
  ]
}
```

- 响应：zip 文件流（blob）
- `archiveName` 可选，默认 "文档资源下载.zip"
- 后端自动去重（若同时包含文件夹及其子资源）

### 2.3 错误处理

- 401：未授权，需跳转登录页
- 403：权限不足
- 资源不存在/已删除/参数错误：返回错误状态码

## 三、技术方案

### 3.1 为什么使用 fetch 而非 axios

现有 `src/utils/request.js` 的 axios 响应拦截器会自动解包 `response.data`，而下载接口返回的是原始文件流，不走 JSON 包装。使用原生 `fetch` 可以：
- 直接获取 blob 响应
- 正确读取 `Content-Disposition` 响应头
- 避免 axios 拦截器干扰

### 3.2 文件变更清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/utils/download.js` | **新建** | 下载工具函数 |
| `src/views/FileList/index.jsx` | **修改** | 添加下载菜单项 + 批量下载按钮 |

## 四、详细设计

### 4.1 新建 `src/utils/download.js`

```js
import { getToken } from './token'

const BASE_URL = import.meta.env.VITE_API_BASE_URL

/**
 * 从 Content-Disposition 响应头中提取文件名
 * 支持两种格式：
 *   filename="xxx"          (legacy)
 *   filename*=UTF-8''xxx    (RFC 5987)
 */
function extractFilename(headers, fallbackName = 'download') {
    const disposition = headers.get('Content-Disposition')
    if (!disposition) return fallbackName

    // RFC 5987 编码（优先）
    const utf8Match = disposition.match(/filename\*=UTF-8''([^;]+)/i)
    if (utf8Match) return decodeURIComponent(utf8Match[1])

    // 传统格式
    const match = disposition.match(/filename="([^"]+)"/)
    if (match) return match[1]

    return fallbackName
}

/**
 * 触发浏览器下载
 */
function triggerBrowserDownload(blob, filename) {
    const url = URL.createObjectURL(blob)
    const a = document.createElement('a')
    a.href = url
    a.download = filename
    document.body.appendChild(a)
    a.click()
    a.remove()
    setTimeout(() => URL.revokeObjectURL(url), 1000)
}

/**
 * 单个资源下载
 * @param {number} status - 资源类型（1=文本 2=文件夹 3=Excel 4=文件）
 * @param {number} id - 资源 ID
 */
export async function downloadSingle(status, id) {
    const token = getToken()
    const url = `${BASE_URL}/document/download/${status}/${id}`

    const response = await fetch(url, {
        method: 'GET',
        headers: { 'Authorization': `Bearer ${token}` }
    })

    if (!response.ok) {
        if (response.status === 401) {
            window.location.hash = '/login'
        }
        throw new Error(`下载失败: ${response.status}`)
    }

    const filename = extractFilename(response.headers, `document_${id}`)
    const blob = await response.blob()
    triggerBrowserDownload(blob, filename)
}

/**
 * 批量资源下载
 * @param {string} archiveName - 压缩包名称
 * @param {Array<{id: number, status: number}>} items - 资源列表
 */
export async function downloadBatch(archiveName, items) {
    const token = getToken()
    const url = `${BASE_URL}/document/download/batch`

    const response = await fetch(url, {
        method: 'POST',
        headers: {
            'Authorization': `Bearer ${token}`,
            'Content-Type': 'application/json'
        },
        body: JSON.stringify({ archiveName, items })
    })

    if (!response.ok) {
        if (response.status === 401) {
            window.location.hash = '/login'
        }
        throw new Error(`批量下载失败: ${response.status}`)
    }

    const filename = extractFilename(response.headers, `${archiveName}.zip`)
    const blob = await response.blob()
    triggerBrowserDownload(blob, filename)
}
```

## 五、注意事项

1. **Content-Disposition 头跨域访问**：fetch 跨域请求默认无法读取 `Content-Disposition` 头。需要后端在 CORS 配置中添加 `Access-Control-Expose-Headers: Content-Disposition`。如果未配置，会使用 fallback 文件名。
2. **不删除旧 `downloadFile`**：`src/apis/file.js` 中的 `downloadFile` 函数暂时保留，新接口完全替代它，但暂不做删除以保持向后兼容。
3. **大文件下载**：当前方案使用 `response.blob()` 一次性读取，如果后续需要支持进度条，可以改用 `ReadableStream` 分块读取。
