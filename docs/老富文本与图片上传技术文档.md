### 1.3 自定义图片 Blot

文件：`src/hooks/useQuillTooBar.jsx`，第6-29行。

默认的 Quill image blot 在序列化时只会保留 `src` 属性，丢弃 `width`、`height`、`style` 等内联样式。项目注册了 `CustomImageFormat` 来解决这个问题：

```js
const BaseImageFormat = Quill.import('formats/image')
const IMAGE_ATTRIBUTES = ['alt', 'height', 'width', 'style']

class CustomImageFormat extends BaseImageFormat {
    static formats(domNode) {
        // 从 DOM <img> 节点提取 alt/height/width/style 属性
        return IMAGE_ATTRIBUTES.reduce((formats, attribute) => {
            if (domNode.hasAttribute(attribute)) {
                formats[attribute] = domNode.getAttribute(attribute)
            }
            return formats
        }, {})
    }

    format(name, value) {
        // 将属性写回 DOM 节点
        if (IMAGE_ATTRIBUTES.includes(name)) {
            if (value) this.domNode.setAttribute(name, value)
            else this.domNode.removeAttribute(name)
            return
        }
        super.format(name, value)
    }
}

Quill.register(CustomImageFormat, true)  // 覆盖默认 image format
```

**作用**：配合 `imageResize` 模块使用时，用户拖拽调整图片尺寸后，`width`、`height`、`style` 属性能在 Quill 的序列化/反序列化过程中完整保留，不会丢失。

### 1.6 查看/编辑文档页面

文件：`src/views/Content/index.jsx`
路由：`#/content/:folder/:id`
导出组件：`MemoContent`

**两种显示模式**：

| 模式 | 条件 | 渲染方式 |
|---|---|---|
| 只读模式 | `isEdit === false`（默认） | `ReactHtmlParser(value)` 渲染 HTML，包裹在 `div.ql-container.ql-snow > div.ql-editor` 中 |
| 编辑模式 | `isEdit === true` | 挂载 `<ReactQuill>` 组件，显示表单和编辑器 |

**只读模式渲染**：

```jsx
{/* 标题与元信息 */}
{ReactHtmlParser(`
    <h1>${title.current}</h1>
    <h2>作者：${author.current}</h2>
    <h3>创建时间：${time.current.createTime}    更新时间：${time.current.updateTime}</h3>
`)}

{/* 正文内容 */}
<div className='ql-container ql-snow' style={{ maxHeight: 'calc(100vh - 220px)' }}>
    <div className='ql-editor'>
        {ReactHtmlParser(value)}
    </div>
</div>
```

通过使用 Quill 的 CSS 类名（`ql-container`、`ql-snow`、`ql-editor`），确保只读模式下文本排版与编辑模式一致，同时避免加载完整的编辑器实例。

**数据加载流程**：

1. `useEffect([param.id])` 触发 → 调用 `getContentDetail(id)`
2. 响应 `res.data` 结构：`{ title, author, content, createTime, updateTime }`
3. `title` / `author` 存入 `useRef`（避免重渲染）
4. `content` 存入 `useState(value)`（驱动编辑器显示）
5. `createTime` / `updateTime` 格式化后存入 `useRef`

**保存机制（双保险）**：

#### 手动保存

点击浮动保存按钮 → `ChangeIsEdit()` → 当前在编辑模式则：

1. 调用 `syncEditorContent()` 获取最新 HTML
2. 调用 `editContent({ title, author, content, id })` API
3. 成功 → 显示"文档更新成功"提示 + 刷新详情
4. 失败 → 显示错误提示
5. 切换 `isEdit` 状态（退出编辑或进入编辑）

#### 自动保存（第93-115行）

```js
useEffect(() => {
    if (!isEdit) return;

    const timer = setTimeout(async () => {
        try {
            const latestContent = syncEditorContent()
            await editContent({
                title: title.current,
                author: author.current,
                content: latestContent,
                id: param.id
            });
            // 静默保存，不显示成功提示
        } catch (e) {
            error({ content: '自动保存失败，请手动保存', delayTime: 2000 });
        }
    }, 2000);  // 2秒防抖

    return () => clearTimeout(timer);
}, [value, isEdit]);
```

- 触发条件：`isEdit === true` 且 `value` 发生变化
- 防抖机制：每次 `value` 变化重置 2 秒定时器
- 成功时静默无提示，失败时提示用户手动保存

### 1.7 内容同步方法

两个页面（`AddContent` / `Content`）都有此方法，逻辑一致：

```js
const syncEditorContent = () => {
    const latestContent = quillRef.current?.getEditor?.()?.root?.innerHTML
    if (typeof latestContent === 'string' && latestContent !== value) {
        setValue(latestContent)
    }
    return typeof latestContent === 'string' ? latestContent : value
}
```

**调用时机**：
- 编辑器 `onBlur` 事件
- 手动保存 / 自动保存执行前

**作用**：通过 Quill ref 直接读取编辑器 DOM 的 `innerHTML`，确保获取到包含图片缩放后样式在内的最新 HTML，而非仅依赖 `onChange` 回调的值。

## 二、图片上传逻辑

### 2.1 富文本编辑器中的图片（base64 内嵌）

**完整流程**：

```
用户点击工具栏 image 按钮
    ↓
浏览器弹出文件选择器
    ↓
Quill 默认 handler 读取文件
    ↓
FileReader 将文件转为 base64 Data URL
    ↓
Quill 插入 <img src="data:image/png;base64,iVBORw0KGgo..." />
    ↓
图片随 HTML 内容一起作为 content 字段保存
    ↓
POST /text/add  或  PUT /text/update  →  后端数据库
```

**关键代码位置**：`src/hooks/useQuillTooBar.jsx` 第38行

```js
// 工具栏配置中包含 'image'，但没有自定义 handler
['link', 'image', 'video'],
```

**特点**：

| 项目 | 说明 |
|---|---|
| 上传方式 | 无自定义 handler，使用 Quill 默认行为 |
| 存储格式 | base64 Data URL 直接嵌入 HTML `<img>` 标签的 `src` 属性 |
| 传输方式 | 作为 JSON `content` 字段的一部分，随整个文档一起发送 |
| 后端存储 | 整个 HTML（含 base64 图片字符串）存入数据库 |
| 与 MinIO 的关系 | 无关联，不走 MinIO 接口 |

**示例**：编辑器中插入一张图片后，保存到后端的 `content` 字段内容形如：

```html
<p>这是一段文字</p>
<p><img src="data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..." width="400" style="width: 400px;"></p>
<p>另一段文字</p>
```

**潜在问题**：

1. **数据库膨胀**：大图片的 base64 编码可能达到数 MB，导致数据库存储压力
2. **传输开销**：base64 编码比二进制大约增加 33% 的体积
3. **加载性能**：每次打开文档都必须传输全部 base64 图片数据
4. **不可复用**：同一图片在不同文档中会重复存储

### 2.2 独立文件上传（MinIO 对象存储）

文件：`src/components/UploadFile/index.jsx`
用于上传普通文件（`status === 4`），与富文本编辑器无关。

**完整流程**：

```
用户点击"选择文件"按钮（Ant Design Upload 组件）
    ↓
customRequest 拦截文件选择，暂存到 selectedFiles 状态
    ↓
自动弹出确认 Modal（显示文件列表和大小）
    ↓
用户确认上传
    ↓
优先调用 uploadFilesBatch() — 批量上传
    ↓ (失败则降级)
逐个调用 uploadFile() — 单文件上传
    ↓
显示全屏 Loading + 模拟进度条
    ↓
上传成功 → 导航回文件列表
```

**关键实现细节**：

#### 文件选择与暂存

```js
const handleCustomRequest = ({ file, onSuccess }) => {
    const originFile = file.originFileObj || file
    // 去重检查（按 name + size 判断）
    // 数量检查（不超过 maxCount）
    // 暂存到 selectedFiles
    // 自动弹出确认 Modal
    onSuccess('success', file)
}
```

- 使用 `customRequest` 拦截 Ant Design Upload 的默认上传行为
- 文件先暂存到本地状态，不立即上传
- 支持 `multiple` 多选，默认最多 `maxCount`（10个）文件
- 去重逻辑：按 `name + size` 判断

#### 上传策略

```js
const handleConfirmUpload = async () => {
    // 1. 优先批量上传
    try {
        response = await uploadFilesBatch({ id, files })
        uploadResults = response?.data || []
    } catch (batchError) {
        // 2. 批量失败，降级为逐个上传
        for (let i = 0; i < files.length; i++) {
            const singleRes = await uploadFile({ id, file: files[i] })
            uploadResults.push({ ... })
        }
    }
}
```

- 先尝试 `/minio/upload/batch` 批量上传
- 批量接口失败时自动降级为逐个调用 `/minio/upload`
- 每个文件独立捕获异常，单个失败不影响其他文件

#### 进度条（模拟）

```js
const progressInterval = setInterval(() => {
    setUploadProgress(prev => {
        if (prev >= 90) { clearInterval(progressInterval); return 90 }
        return prev + 10
    })
}, 200)  // 每200ms增加10%，上限90%
// 上传完成后直接设为100%
```

进度条是前端模拟的，不反映真实上传进度。

#### 文件夹 ID 处理

```js
const getFolderId = () => {
    // 优先使用 props.folderId
    // 其次使用 URL 参数 param.id
    // 都无效则返回 null
}
```

#### 结果处理

上传成功后，组件调用 `onChange` 回调通知父组件，并携带每个文件的上传结果：


**上传接口 FormData 构造**：

```js
// 单文件上传
const data = new FormData()
data.append('id', intId.toString())   // 可选，关联文件夹
data.append('file', file)             // 必填，文件对象

// 批量上传
const data = new FormData()
files.forEach(file => data.append('files', file))  // 注意参数名是 files
data.append('id', intId.toString())                 // 可选
```

**下载接口实现**：

```js
const downloadFile = (id) => {
    return request({
        url: `/minio/download/${id}`,
        method: 'GET',
        responseType: 'blob',
    }).then(response => {
        const blob = new Blob([response.data]);
        const url = window.URL.createObjectURL(blob);
        const link = document.createElement('a');
        link.href = url;
        link.setAttribute('download', `file_${id}`);
        document.body.appendChild(link);
        link.click();
        link.remove();
        window.URL.revokeObjectURL(url);
    });
}
```

## 六、现状总结与优化建议

### 现状总结

| 维度 | 富文本图片 | 独立文件上传 |
|---|---|---|
| 存储方式 | base64 内嵌 HTML | MinIO 对象存储 |
| 上传接口 | 无（Quill 默认处理） | `/minio/upload`、`/minio/upload/batch` |
| 数据传输 | 随文档 JSON 一起发送 | 独立 FormData 上传 |
| 预览方式 | Quill 编辑器直接渲染 | `/minio/preview/{id}` 返回 URL |
| 两套系统关系 | **完全独立，互不关联** | |

### 优化建议

如需改进富文本编辑器中的图片处理，可添加自定义 Quill image handler：

```js
// 在 useQuillTooBar.jsx 中添加自定义 handler
const modules = {
    toolbar: {
        container: [ /* 同现有配置 */ ],
        handlers: {
            image: function() {
                const input = document.createElement('input')
                input.setAttribute('type', 'file')
                input.setAttribute('accept', 'image/*')
                input.click()
                input.onchange = async () => {
                    const file = input.files[0]
                    const formData = new FormData()
                    formData.append('file', file)
                    // 调用 MinIO 上传接口
                    const res = await uploadFile({ file })
                    const range = this.quill.getSelection(true)
                    // 插入 MinIO 返回的 URL 而非 base64
                    this.quill.insertEmbed(range.index, 'image', res.data.url)
                }
            }
        }
    },
    // ... 其他模块
}
```

这样可以将图片从 base64 内嵌改为 URL 引用，减少数据库存储压力和网络传输开销。
