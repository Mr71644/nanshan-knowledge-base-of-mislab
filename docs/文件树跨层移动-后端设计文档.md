# 文件树跨层移动 — 后端设计文档

## 一、需求背景

前端已实现文件树的同层拖拽排序（`PUT /home/sort`）。现在需要新增跨层移动功能：将文件/文件夹从一个文件夹移动到另一个文件夹中。

## 二、新增接口

### 2.1 移动接口

```
PUT /home/move
Content-Type: application/json
Authorization: Bearer <token>
```

**请求体：**

```json
{
  "itemId": 12,
  "itemStatus": 2,
  "targetFolderId": 5
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `itemId` | `number` | 被移动的文件/文件夹 ID |
| `itemStatus` | `number` | 类型：1=文档、2=文件夹、3=Excel、4=文件 |
| `targetFolderId` | `number \| null` | 目标文件夹 ID，`null` 表示移到根目录 |

**响应：**

```json
{
  "code": 200,
  "message": "success"
}
```

### 2.2 后端处理逻辑

1. **校验权限**：用户对源文件夹和目标文件夹都有编辑权限
2. **校验目标存在**：`targetFolderId` 对应的文件夹存在（除非为 `null`）
3. **校验非循环**：如果 `itemStatus === 2`（文件夹），检查 `targetFolderId` 不是被移动文件夹自身，也不是其子文件夹
4. **更新记录**：根据 `itemStatus` 确定对应的数据表，更新 `folder_id` / `parent_id` 为 `targetFolderId`
5. **更新排序**：将 `sort_order` 设为目标文件夹下同级最大值 + 1（排在末尾）

```java
// 伪代码
String table = getTableByStatus(itemStatus);
// table: 1→text, 2→folder, 3→excel, 4→minio_file

// 获取目标文件夹下的最大 sort_order
Integer maxSortOrder = jdbcTemplate.queryForObject(
    "SELECT COALESCE(MAX(sort_order), -1) FROM " + table + " WHERE folder_id = ?",
    Integer.class, targetFolderId
);

// 更新 folder_id 和 sort_order
jdbcTemplate.update(
    "UPDATE " + table + " SET folder_id = ?, sort_order = ? WHERE id = ?",
    targetFolderId, maxSortOrder + 1, itemId
);
```

### 2.3 循环引用校验（仅文件夹移动时）

```
输入：folderId = 12（被移动的文件夹），targetFolderId = 5（目标文件夹）

逻辑：
1. 如果 targetFolderId === folderId → 拒绝（不能移入自身）
2. 从 targetFolderId 开始向上遍历父级链：
   - 如果某一级的 id === folderId → 拒绝（不能移入自己的子文件夹）
3. 否则通过
```

```sql
-- 向上查找父级链（递归），检查是否包含 folderId
-- 具体实现取决于数据库是否支持递归查询（MySQL 8.0+ CTE / PostgreSQL）
```

### 2.4 错误响应

| HTTP 状态码 | 场景 |
|-------------|------|
| 401 | 未登录 / token 过期 |
| 403 | 无编辑权限 |
| 400 | `itemId` 不存在、`targetFolderId` 不存在、循环引用 |

## 三、接口汇总

| 接口 | 类型 | 说明 |
|------|------|------|
| `PUT /home/sort` | 已有 | 同层排序 |
| `PUT /home/move` | **新增** | 跨层移动 |

## 四、数据库变更

本次无额外数据库结构变更。移动操作只更新 `folder_id` 和 `sort_order` 字段（已在同层排序功能中添加）。

## 五、注意事项

1. **事务处理**：`PUT /home/move` 中的操作应在同一事务中执行
2. **权限校验**：需同时校验源文件夹和目标文件夹的编辑权限
3. **子树移动**：移动文件夹时，其子项的 `folder_id` 无需更新（因为它们通过文件夹的 `parent_id` 关联，不是直接关联顶层 `folder_id`）
4. **`GET /home/tree`** 无需变更，已按 `sort_order` 排序返回
