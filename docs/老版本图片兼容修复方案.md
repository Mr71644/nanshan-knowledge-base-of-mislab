# 老版本图片上传兼容修复方案

> 生成日期：2026-05-15

---

## 一、问题背景

项目从 Quill 富文本编辑器（HTML 输出）迁移到了 Markdown 编辑器。旧文档内容为 HTML 格式，图片以 base64 内嵌方式存储：

```html
<p>这是一段文字</p>
<p><img src="data:image/png;base64,iVBORw0KGgo..." width="400" style="width: 400px;"></p>
<p>另一段文字</p>
```

当前所有内容均使用 ReactMarkdown 渲染，旧 HTML 内容会以原始文本形式显示，base64 图片无法渲染。

## 二、修复目标

1. **预览模式**：旧 HTML 文档使用原有方式正确显示（HTML 渲染 + base64 图片），与旧版体验一致
2. **编辑模式**：用户点击编辑时，弹出确认提示，告知将进行格式迁移
3. **迁移过程**：
   - 将 base64 图片提取并上传到 MinIO，替换为 MinIO 预览 URL
   - 将 HTML 文本转为 Markdown 格式
4. **迁移后**：内容以 Markdown 格式保存，图片使用 MinIO URL，与新建文档的格式完全一致，可正常使用 Markdown 编辑器进行后续编辑（textarea 编辑 + ReactMarkdown 实时预览 + 自动保存）
5. 新 Markdown 文档不受任何影响

## 三、用户交互流程

### 3.1 旧文档预览

```
打开旧文档
  → 检测到旧 HTML 格式
  → 使用 react-html-parser 渲染 HTML（base64 图片正常显示）
  → 底部显示提示横幅："此文档为旧版格式，点击编辑按钮可迁移为 Markdown 格式"
```

### 3.2 旧文档编辑（迁移）

```
用户点击编辑按钮
  → 弹出确认对话框（Modal）：
     "此文档使用旧版富文本编辑器创建，迁移后将转换为 Markdown 格式。
      文档中的图片将上传至服务器存储，文档格式转换后不可恢复。
      是否确认迁移？"
  → 用户点击"取消" → 不做任何操作，保持预览
  → 用户点击"确认迁移" → 开始迁移流程
```

### 3.3 迁移流程

```
确认迁移
  ↓
显示 Loading："正在迁移文档格式..."
  ↓
1. 提取 HTML 中所有 base64 图片（<img src="data:image/...">）
  ↓
2. 逐张上传到 MinIO：
   - 将 base64 转为 File 对象
   - 调用 uploadMarkdownImage({ file, id, folderId })
   - 获取 fileId → 调用 previewMarkdownImage(fileId) 获取预览 URL
   - 建立 base64 → 预览 URL 的映射表
  ↓
3. 替换 HTML 中的 base64 src 为预览 URL
  ↓
4. 使用 turndown 将 HTML 转为 Markdown
  ↓
5. 自动保存到后端（PUT /text/update）
  ↓
6. 进入 Markdown 编辑模式（textarea + 实时预览）
```

### 4.2 新增文件：`src/utils/contentType.js` — 内容格式检测

```javascript
/**
 * 检测内容是否为旧版 HTML（来自 Quill 编辑器）
 */
export function isHtmlContent(content) {
    if (!content || typeof content !== 'string') return false

    const trimmed = content.trim()
    if (!trimmed) return false

    const htmlBlockPattern = /<(p|div|span|h[1-6]|ul|ol|li|table|thead|tbody|tr|th|td|blockquote|pre|img|br|hr|strong|em|a |sub|sup|u|s )\b[^>]*>/i
    const dataUriPattern = /data:image\/[a-zA-Z+]+;base64,/i

    return htmlBlockPattern.test(trimmed) || dataUriPattern.test(trimmed)
}
```

### 4.3 新增文件：`src/utils/htmlToMarkdown.js` — HTML→Markdown 转换

```javascript
import TurndownService from 'turndown'

/**
 * 将 HTML 内容转为 Markdown
 * 调用前应已将 base64 图片替换为 MinIO URL
 */
export function convertHtmlToMarkdown(html) {
    const turndown = new TurndownService({
        headingStyle: 'atx',        // 使用 # 风格标题
        bulletListMarker: '-',      // 无序列表使用 -
        codeBlockStyle: 'fenced',   // 使用 ``` 代码块
    })

    turndown.addRule('image', {
        filter: 'img',
        replacement: (content, node) => {
            const src = node.getAttribute('src')
            const alt = node.getAttribute('alt') || '图片'
            if (!src) return ''
            return `![${alt}](${src})`
        }
    })

    return turndown.turndown(html)
}
```

### 4.4 新增文件：`src/utils/migrateImages.js` — base64 图片迁移到 MinIO

```javascript
import { uploadMarkdownImage, previewMarkdownImage } from '@/apis/image'

/**
 * 将 HTML 中的 base64 图片上传到 MinIO，返回替换后的 HTML 和图片映射表
 * @param {string} html - 包含 base64 图片的 HTML 内容
 * @param {string|number} folderId - 文件夹 ID
 * @param {function} onProgress - 进度回调 (current, total)
 * @returns {Promise<{ html: string, imageMap: Map }>}
 */
export async function migrateBase64Images(html, folderId, onProgress) {
    // 正则匹配所有 base64 图片
    const imgRegex = /<img[^>]+src="(data:image\/([^;]+);base64,([^"]+))"[^>]*>/gi
    const matches = [...html.matchAll(imgRegex)]

    if (matches.length === 0) {
        return { html, imageMap: new Map() }
    }

    const imageMap = new Map() // base64 → MinIO URL
    let migratedHtml = html

    for (let i = 0; i < matches.length; i++) {
        const fullMatch = matches[i][0]    // 完整 <img> 标签
        const dataUri = matches[i][1]       // data:image/png;base64,...
        const mimeType = matches[i][2]      // png, jpeg, etc.
        const base64Data = matches[i][3]    // base64 编码数据

        onProgress?.(i + 1, matches.length)

        try {
            // 1. base64 → File 对象
            const byteCharacters = atob(base64Data)
            const byteNumbers = new Array(byteCharacters.length)
            for (let j = 0; j < byteCharacters.length; j++) {
                byteNumbers[j] = byteCharacters.charCodeAt(j)
            }
            const byteArray = new Uint8Array(byteNumbers)
            const blob = new Blob([byteArray], { type: `image/${mimeType}` })
            const file = new File([blob], `migrated_image_${i}.${mimeType}`, { type: `image/${mimeType}` })

            // 2. 上传到 MinIO
            const uploadParams = { file }
            const parsedId = parseInt(folderId, 10)
            if (!isNaN(parsedId) && parsedId > 0) {
                uploadParams.id = parsedId
                uploadParams.folderId = parsedId
            }
            const uploadRes = await uploadMarkdownImage(uploadParams)

            // 3. 提取 fileId
            let fileId = null
            if (typeof uploadRes === 'string') fileId = uploadRes
            else if (uploadRes.data?.id) fileId = uploadRes.data.id
            else if (uploadRes.data?.fileId) fileId = uploadRes.data.fileId
            else if (uploadRes.data?.file_id) fileId = uploadRes.data.file_id
            else if (uploadRes.id) fileId = uploadRes.id

            if (fileId) {
                // 4. 获取预览 URL
                const previewRes = await previewMarkdownImage(fileId)
                let url = null
                if (typeof previewRes === 'string') url = previewRes
                else if (previewRes.data) url = previewRes.data

                if (url) {
                    imageMap.set(dataUri, url)
                    // 替换 HTML 中的 base64 为 MinIO URL
                    migratedHtml = migratedHtml.replace(dataUri, url)
                }
            }
        } catch (e) {
            console.error(`图片迁移失败 (第${i + 1}张):`, e)
            // 单张失败不影响其他图片，保留原始 base64
        }
    }

    return { html: migratedHtml, imageMap }
}
```

### 4.5 新增文件：`src/components/HtmlContent/index.jsx` — HTML 只读渲染组件

import ReactHtmlParser from 'react-html-parser'

/**
 * 渲染旧版 HTML 内容（来自 Quill 编辑器）

## 七、数据流图

### 旧文档预览（不迁移）

```
GET /text/get/{id} → content (HTML + base64)
       ↓
isHtmlContent(content) === true
       ↓
<HtmlContent> + react-html-parser 渲染 HTML（base64 图片正常显示）
       ↓
提示横幅："此文档为旧版格式，点击编辑按钮可迁移"
```

### 旧文档编辑（确认迁移）

```
用户点击编辑 → 弹出确认对话框
       ↓
用户确认迁移
       ↓
migrateBase64Images(html, folderId)
  → 提取所有 base64 图片
  → 逐张上传到 MinIO（uploadMarkdownImage → previewMarkdownImage）
  → 替换 HTML 中的 base64 为 MinIO URL
       ↓
convertHtmlToMarkdown(替换后的HTML)
  → HTML 转 Markdown
       ↓
自动保存到后端（PUT /text/update）
       ↓
进入 Markdown 编辑模式（textarea + 实时预览）
       ↓
下次打开 → isHtmlContent() === false → 走正常 Markdown 流程
```

**迁移后持续编辑保证**：

迁移后的内容格式与新建文档上传图片后的格式完全相同：
- 文本为标准 Markdown 语法（`# 标题`、`**粗体**`、`- 列表` 等）
- 图片为 `![图片](MinIO预览URL)` 格式，与手动上传图片产生的格式一致
- textarea 编辑、ReactMarkdown 实时预览、自动保存、手动保存均正常工作
- 再次打开文档时不再触发兼容逻辑，直接走 Markdown 渲染流程

### 新文档（不受影响）

```
GET /text/get/{id} → content (Markdown)
       ↓
isHtmlContent(content) === false
       ↓
<ReactMarkdown> 渲染（现有逻辑不变）
```

## 十、潜在风险

| 风险 | 缓解措施 |
|------|----------|
| HTML→Markdown 转换不完美（复杂表格、嵌套列表） | turndown 对常见 HTML 支持良好；转换后用户可手动调整 |
| 大量/大体积 base64 图片迁移耗时长 | 显示 Loading 和进度提示；单张失败不阻断 |
| 迁移后不可恢复 | 确认对话框明确提示"不可恢复" |
| 检测误判（Markdown 中包含 HTML 标签） | 检测函数匹配块级结构标签，Markdown 中极少出现 |
| 网络中断导致图片上传失败 | 单张失败 try-catch 包裹，保留原始 base64 继续转换 |
