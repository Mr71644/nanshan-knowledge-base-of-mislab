# 文件拖拽移动功能 — 系统分析文档

## 一、功能概述

文件拖拽移动功能允许用户在系统左侧的文件树中，通过鼠标拖拽的方式将文件或文件夹移动到目标位置。该功能同时支持**跨文件夹移动**和**同级排序调整**两种操作场景。

移动操作仅改变节点在目录树中的父级关系和显示顺序，不改变已上传文件在对象存储（MinIO）中的实际路径，因此文件移动后历史链接仍然可用。

---

## 二、支持的节点类型

| 类型 | 说明 |
|---|---|
| 文档 | 富文本内容 |
| 文件夹 | 目录节点 |
| Excel | 电子表格 |
| 普通文件 | 附件/图片等 |

---

## 三、全流程说明

### 3.1 用户操作（前端交互）

用户在左侧文件树中拖拽节点时，系统按以下步骤响应：

**第一步 — 判断是否允许拖拽**

用户按下鼠标开始拖拽时，系统检查当前节点是否可拖拽。管理员可拖拽任意节点；普通用户仅可拖拽拥有编辑权限的节点。搜索模式下禁止拖拽。

**第二步 — 判断是否允许放置**

拖拽过程中，当鼠标悬停到目标位置时，系统实时判断放置是否合法：
- 仅允许将节点放入文件夹内（不能放入文件上）
- 普通用户需要对目标文件夹拥有编辑权限
- 文件夹不能移动到自身或自身的子级目录下（防循环校验）

不合法的放置位置会被自动拒绝，不产生任何操作。

**第三步 — 确认并执行**

松开鼠标后，系统区分两种情况：

| 场景 | 触发条件 | 用户交互 |
|---|---|---|
| 跨文件夹移动 | 节点被拖入不同的文件夹 | 弹出确认对话框，用户确认后执行 |
| 同级排序调整 | 节点在同一文件夹内调整顺序 | 直接执行，无需确认 |

### 3.2 前端请求

用户确认移动后，前端根据操作类型向后端发送请求：

**移动请求（跨文件夹）**

```
PUT /home/move
```

| 参数 | 说明 |
|---|---|
| itemId | 被移动节点的 ID |
| itemStatus | 节点类型（1=文档, 2=文件夹, 3=Excel, 4=普通文件） |
| targetFolderId | 目标文件夹 ID，为空时表示移动到根目录 |

**排序请求（同级调整顺序）**

```
PUT /home/sort
```

| 参数 | 说明 |
|---|---|
| parentFolderId | 父文件夹 ID |
| orderedIds | 调整后的节点排列顺序列表 |

请求发出后，前端先在本地更新文件树显示（乐观更新），使界面即时响应用户操作。

### 3.3 后端处理

后端接收到移动请求后，在数据库事务中依次执行以下校验和处理：

**（1）参数校验**

确认节点 ID 和类型不为空，类型值在有效范围内（1-4）。

**（2）节点存在性校验**

根据节点类型查询对应的数据表，确认被移动的节点存在且未删除。若不存在则返回错误。

**（3）目标文件夹校验**

若目标不是根目录，则在文件夹表中确认目标文件夹存在且未删除。

**（4）权限校验**

| 校验对象 | 规则 |
|---|---|
| 源文件夹 | 用户必须拥有编辑权限 |
| 目标文件夹 | 用户必须拥有编辑权限 |
| 文件夹本身（仅移动文件夹时） | 用户必须对该文件夹拥有编辑权限 |
| 根目录 | 仅超级管理员可操作 |

**（5）防循环校验（仅移动文件夹时）**

系统递归检查目标文件夹是否是被移动文件夹的子级。若检测到循环则拒绝操作，防止目录树结构损坏。

```
示例：A → B → C 的目录结构中，不允许将 A 移动到 B 或 C 下面
```

**（6）计算排序号**

系统跨所有节点类型（文件夹、文档、Excel、普通文件）统计目标位置下的最大排序号，新排序号 = 最大排序号 + 1。若目标位置为空则排序号为 0。

**（7）数据库更新**

根据节点类型更新对应数据表中的三个字段：父级字段、排序号、更新时间。

### 3.4 数据库操作

移动操作涉及以下四张数据表，根据节点类型更新对应的表：

| 节点类型 | 数据表 | 更新的父级字段 |
|---|---|---|
| 文档 | text | folder_id |
| 文件夹 | folders | parent_id |
| Excel | excel | folder_id |
| 普通文件 | file | folder_id |

每次更新同时写入新的排序号（sort_order）和当前时间戳（update_time）。

所有操作在同一个数据库事务中执行。若任一步骤失败，整个移动操作回滚，数据不会被部分修改。

---

## 四、异常处理

| 异常情况 | 返回状态码 | 说明 |
|---|---|---|
| 参数缺失或无效 | 400 | 节点 ID 为空、类型不在有效范围内等 |
| 节点或目标文件夹不存在 | 400 | 查询不到对应的未删除记录 |
| 移动到自身或子文件夹 | 400 | 防循环校验未通过 |
| 未登录或登录过期 | 401 | Token 缺失或已失效，自动跳转登录页 |
| 无编辑权限 | 403 | 普通用户操作了无权限的文件夹 |
| 服务器内部异常 | 500 | 未预期的运行时错误 |

前端接收到错误响应后，会撤销本地的界面更新，恢复到移动前的状态，并向用户提示错误信息。

        │
        ▼

  拒绝   弹出确认框（跨文件夹时）

           ▼

        │
        ▼
  参数校验 → 节点存在性校验 → 目标文件夹校验
        │
        ▼

        │
        ▼

        ▼

        ▼

    │      │

  当前   提示错误信息

## 六、技术要点总结

1. **基于 Ant Design Tree 组件**实现拖拽交互，无需引入额外的拖拽库，减少依赖。
2. **乐观更新策略**：移动请求发出后前端立即更新文件树显示，提升用户操作体验；若后端返回失败则自动回滚。
3. **防循环校验**：文件夹移动时递归检查目标是否为自身子级，防止树形结构出现循环引用。
4. **跨表统一排序**：排序号跨四张数据表统一计算，确保不同类型的节点在同一层级内有合理的显示顺序。
5. **事务保护**：所有数据库更新在同一事务内完成，保证数据一致性。
6. **权限分层**：管理员拥有完全操作权限，普通用户仅可操作拥有编辑权限的节点。
