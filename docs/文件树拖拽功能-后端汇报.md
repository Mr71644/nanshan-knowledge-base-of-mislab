# 文件树拖拽排序与移动功能 — 后端汇报

## 一、功能概述

为配合前端文件树拖拽交互，后端新增两个接口，分别支持同层排序和跨层移动：

| 接口 | 方法 | 功能 |
|------|------|------|
| `/home/sort` | PUT | 同一文件夹内的文件/文件夹排序 |
| `/home/move` | PUT | 将文件/文件夹移动到指定文件夹 |

## 二、接口设计

### 2.1 同层排序（`PUT /home/sort`）

**场景**：用户在文件树中拖拽调整同级节点的显示顺序。

**请求参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `parentFolderId` | number / null | 父文件夹 ID，null 表示根目录 |
| `orderedIds` | Array | 按新顺序排列的所有兄弟节点，每项包含 `id` 和 `status`（类型） |

**设计思路**：
- 前端发送该层级下**完整的有序列表**，后端批量更新 `sort_order` 字段
- `status` 字段标识节点类型（1=文档、2=文件夹、3=Excel、4=文件），不同类型可能存储在不同表中
- 使用事务保证批量更新的原子性

### 2.2 跨层移动（`PUT /home/move`）

**场景**：用户将文件/文件夹从一个文件夹拖到另一个文件夹中。

**请求参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `itemId` | number | 被移动的文件/文件夹 ID |
| `itemStatus` | number | 类型（1=文档 2=文件夹 3=Excel 4=文件） |
| `targetFolderId` | number / null | 目标文件夹 ID，null 表示移到根目录 |

**设计思路**：
- 根据 `itemStatus` 定位对应数据表，更新 `folder_id`（所属文件夹）
- 移动后 `sort_order` 设为目标文件夹下最大值 +1，排在末尾
- 移动文件夹时，其子项无需额外处理（通过文件夹的层级关系自动关联）

## 三、数据库变更

在文档、文件夹、Excel、文件四张表中新增 `sort_order` 整型字段（默认值 0）：

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `sort_order` | INT | 0 | 同级排序权重，值越小越靠前 |

**排序规则**：`ORDER BY pinned DESC, sort_order ASC, update_time DESC`

- 置顶项优先
- 其次按自定义排序
- 最后按更新时间降序（兜底）

## 四、安全校验

| 校验项 | 说明 |
|--------|------|
| 权限校验 | 用户需对涉及的文件夹有编辑权限 |
| 目标存在性 | 目标文件夹必须存在（除非移到根目录） |
| 循环引用检测 | 不允许将文件夹移入自身或自身的子文件夹中 |
| 事务保护 | 排序和移动操作均在事务中执行，保证数据一致性 |
