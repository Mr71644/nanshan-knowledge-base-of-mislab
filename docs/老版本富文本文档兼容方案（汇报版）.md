# 老版本富文本文档兼容方案

> MISLab 知识库系统 — 前端兼容性修复

---

## 一、背景

项目近期将文档编辑器从 **Quill 富文本编辑器**（HTML 格式）升级为 **Markdown 编辑器**。新编辑器已正常投入使用，但数据库中仍存在大量旧文档，其内容以 HTML 格式存储，图片以 base64 编码内嵌在文档中。

当前系统统一使用 Markdown 渲染器显示所有文档，导致旧文档出现以下问题：

- 文档内容显示为原始 HTML 标签文本，无法正常阅读
- 内嵌的 base64 图片完全无法渲染显示

## 二、目标

1. **旧文档可正常查看** — 用户打开旧文档时，内容与图片正常显示
2. **旧文档可平滑迁移** — 用户可将旧文档一键迁移为 Markdown 格式
3. **迁移后可继续编辑** — 迁移后的文档与新建文档格式一致，支持完整的 Markdown 编辑功能
4. **新文档不受影响** — 所有新建文档的功能保持不变

## 三、方案设计

### 3.1 整体思路

采用 **"预览兼容 + 按需迁移"** 的策略：

- **预览阶段**：自动识别旧格式文档，使用 HTML 方式渲染，保证正常查看
- **迁移阶段**：用户主动触发迁移，将内容转为 Markdown 格式

### 3.2 用户操作流程

```
用户打开旧文档
       ↓
系统自动检测为旧格式
       ↓
以 HTML 方式正常渲染（图片正常显示）
底部显示提示："此文档为旧版格式，点击编辑按钮可迁移"
       ↓
用户点击编辑按钮
       ↓
弹出确认对话框：
  "此文档使用旧版编辑器创建，迁移后将转换为 Markdown 格式，
   图片将上传至服务器存储，转换后不可恢复。是否确认迁移？"
       ↓
用户确认 → 自动执行迁移
用户取消 → 保持预览状态，不做任何修改
```

### 3.3 迁移执行流程

```
1. 扫描文档中的 base64 图片
       ↓
2. 逐张上传至 MinIO 对象存储，获取服务器 URL
       ↓
3. 将文档中的 base64 图片替换为 MinIO URL
       ↓
4. 将 HTML 文本转换为 Markdown 格式
       ↓
5. 自动保存转换后的 Markdown 内容
       ↓
6. 进入 Markdown 编辑模式，用户可正常编辑
```

### 3.4 迁移后效果

| 项目 | 迁移前 | 迁移后 |
|------|--------|--------|
| 内容格式 | HTML | Markdown |
| 图片存储 | base64 内嵌文档 | MinIO 服务器独立存储 |
| 图片引用 | `<img src="data:image/...">` | `![图片](MinIO URL)` |
| 查看方式 | HTML 渲染 | Markdown 渲染 |
| 编辑方式 | 不支持 | 完整 Markdown 编辑器 |
| 数据库体积 | 大（base64 占用空间） | 小（仅存 URL） |

## 四、技术实现概览

### 4.1 内容格式自动检测

系统在加载文档时自动检测内容格式，通过识别 HTML 标签（`<p>`、`<img>`、`<strong>` 等）和 base64 数据 URI 来判断文档类型。检测过程对用户完全透明。

### 4.2 旧文档预览渲染

使用 `react-html-parser` 库将 HTML 内容解析为 React 组件并渲染，确保旧文档中的文本排版、图片、列表等元素正确显示，与旧版体验一致。

### 4.3 图片迁移至 MinIO

遍历文档中的所有 base64 图片，将每张图片：
- 解码为二进制文件
- 调用 MinIO 上传接口存储
- 获取服务器预览 URL 替换原始 base64 数据

单张图片上传失败不影响其他图片，系统会保留该图片的原始数据继续完成迁移。

### 4.4 HTML 转 Markdown

使用 `turndown` 库将替换图片后的 HTML 转换为标准 Markdown 语法，包括：
- 标题、加粗、斜体、列表等文本格式转换
- 图片转换为 Markdown 图片语法 `![描述](URL)`
- 表格、代码块等复杂结构的转换

### 4.5 涉及的文件变更

| 变更类型 | 文件 | 说明 |
|----------|------|------|
| 新增 | 内容格式检测模块 | 自动识别 HTML / Markdown 格式 |
| 新增 | HTML→Markdown 转换模块 | 使用 turndown 库实现格式转换 |
| 新增 | 图片迁移模块 | base64 提取、上传、URL 替换 |
| 新增 | HTML 渲染组件 | 旧文档只读预览 |
| 新增 | turndown 依赖 | HTML→Markdown 转换引擎 |
| 修改 | 文档查看/编辑页面 | 集成兼容逻辑与条件渲染 |
| 修改 | 页面样式 | 迁移提示横幅、Loading 遮罩 |

## 五、安全性保障

- 迁移操作需用户**主动确认**，系统不会自动修改任何旧文档
- 确认对话框明确提示"转换后不可恢复"
- 用户可选择**取消**，保持旧格式不变继续查看
- 图片上传失败时保留原始数据，不造成数据丢失

## 六、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| HTML 转 Markdown 不完美 | 部分复杂排版可能需要手动调整 | 支持迁移后手动编辑修正；常见格式（标题、列表、加粗、图片）转换准确 |
| 单张图片上传失败 | 该图片暂时无法显示 | 保留原始 base64 数据，其他图片正常迁移，不阻断流程 |
| 迁移耗时较长 | 用户体验等待 | 显示 Loading 遮罩和进度提示 |
| 迁移不可逆 | 无法回退旧格式 | 确认对话框明确告知，用户可选择不迁移 |

## 七、总结

本方案采用"预览兼容 + 按需迁移"的渐进式策略，用户无需一次性迁移所有旧文档，而是在需要编辑某个旧文档时才触发迁移。既保证了旧文档的可读性，又实现了向新格式的平滑过渡，同时对系统现有功能零影响。
