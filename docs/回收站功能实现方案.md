# 回收站功能实现方案

## 一、功能概述

在 Home 页面操作栏中新增"回收站"入口按钮，点击后以右侧 Drawer 抽屉形式展示回收站管理界面，支持以下功能：

| 功能 | 说明 |
|---|---|
| 回收站列表 | 服务端分页、类型筛选（全部/在线文档/文件夹/Excel/普通文件）、关键词搜索 |
| 恢复资源 | 下拉菜单提供"还原到原目录"和"选择目录还原"两个选项；选择目录时弹出文件夹树选择器 |
| 彻底删除 | 二次确认后彻底删除，不可恢复 |
| 批量操作 | 支持批量恢复和批量彻底删除 |
| 清空回收站 | 一键彻底删除所有回收站资源，需二次确认 |

---

## 二、后端接口

> 以下接口已由后端实现，前端直接对接。

### 2.1 回收站列表

```
GET /recycle-bin/list?current=1&pageSize=20&type=4&keyword=合同
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `current` | 否 | 页码，默认 1 |
| `pageSize` | 否 | 每页数量，默认 20，最大 100 |
| `type` | 否 | 资源类型：1=文本 2=文件夹 3=Excel 4=文件。不传=全部 |
| `keyword` | 否 | 按名称模糊搜索 |

返回字段：

| 字段 | 说明 |
|---|---|
| `id` | 资源 ID |
| `status` | 资源类型（1/2/3/4） |
| `typeName` | 类型中文名（如"文件"） |
| `name` | 资源名称 |
| `originalPath` | 原始路径展示 |
| `owner` | 资源所有者 |
| `deletedBy` | 删除操作人 |
| `deletedAt` | 删除时间 |
| `canRestore` | 是否可直接恢复到原目录 |
| `canPurge` | 是否可彻底删除 |

### 2.2 恢复资源

```
POST /recycle-bin/restore
```

```json
{
    "items": [{ "id": 9, "status": 4 }],
    "targetFolderId": 12,
    "renameOnConflict": true
}
```

| 字段 | 说明 |
|---|---|
| `items` | 要恢复的资源列表，每项 `{id, status}` |
| `targetFolderId` | 目标文件夹 ID。不传或 `null` 表示恢复到原目录；传具体 ID 表示恢复到指定文件夹 |
| `renameOnConflict` | 同名冲突时是否自动重命名 |

### 2.3 彻底删除

```
DELETE /recycle-bin/purge
```

```json
{
    "items": [{ "id": 9, "status": 4 }]
}
```

> 注意：这是带请求体的 DELETE 请求。

## 四、各文件详细设计

### 4.1 `src/apis/recycleBin.js`

```js
import { request } from "@/utils"

const getRecycleBinList = ({ current, pageSize, type, keyword }) => {
    return request({
        url: '/recycle-bin/list',
        method: 'GET',
        params: { current, pageSize, type, keyword }
    })
}

const restoreRecycleBinItems = ({ items, targetFolderId, renameOnConflict }) => {
    return request({
        url: '/recycle-bin/restore',
        method: 'POST',
        data: { items, targetFolderId, renameOnConflict }
    })
}

const purgeRecycleBinItems = ({ items }) => {
    return request({
        url: '/recycle-bin/purge',
        method: 'DELETE',
        data: { items }
    })
}

export { getRecycleBinList, restoreRecycleBinItems, purgeRecycleBinItems }
```

#### 交互逻辑

**1. 打开 Drawer**
- `useEffect` 监听 `open` 变为 true 时调用 `fetchList()`
- `destroyOnClose=true` 确保关闭后重置状态

**2. 单项还原 `handleRestore(record)`**

```
canRestore=true 时：
    直接调用 restoreRecycleBinItems({
        items: [{ id, status }],
        targetFolderId: null,
        renameOnConflict: true
    })
    成功后从 selectedRowKeys/selectedRows 中移除该条目
```

**3. 选择目录还原 `openFolderPicker(items)`**

```
设置 pendingRestoreItems = items
设置 targetFolderId = undefined
加载文件夹树
打开文件夹选择器 Modal
```

**4. 批量还原 `handleBatchRestore()`**

```
全部 canRestore=true → 弹出确认框 → 直接批量恢复（targetFolderId: null）
有 canRestore=false → 打开文件夹选择器，所有选中项恢复到用户选择的目录
```

**5. 永久删除**
- 单项：`Popconfirm` 二次确认 → 调用 purge API → 从 selectedRowKeys/selectedRows 中移除该条目
- 批量：`Modal.confirm` 二次确认 → 调用 purge API

**6. 清空回收站 `handleEmptyAll()`**
- 分页循环获取全部记录（pageSize=100）
- 拼成 items 数组后一次性调用 purge API

**7. 文件夹选择器（Modal）**
- 复用 `getFolderTree()` API（来自 `src/apis/folder.js`）
- 只展示 `status=2` 的文件夹节点
- `targetFolderId` 状态：`undefined`=未选择，具体数字=选中的文件夹 ID
- 确认时校验：未选择文件夹则提示"请选择目标文件夹"
- 确认后调用 restore API，仅在选了具体文件夹时传 `targetFolderId`

**8. 恢复成功后刷新父组件**
- 调用 `navigate(location.pathname, { state: { refresh: Date.now() } })` 触发 Home 和 FileList 自动刷新

## 六、注意事项

1. **DELETE 请求体**：项目已有先例（`delBatch`），axios 支持带 body 的 DELETE 请求
2. **列表 API 响应格式**：后端返回 `{ data: { records: [...], total: N, current, pageSize } }`
3. **清空回收站分页**：分页循环获取全部记录再一次性 purge，设置最大页数保护（100 页）防止死循环
4. **恢复后刷新**：利用现有 `location.state.refresh` 机制通知父组件刷新，无需额外回调
5. **选中状态同步**：单项恢复/删除成功后，需从 `selectedRowKeys` 和 `selectedRows` 中移除已操作的条目，避免后续批量操作携带已失效的 ID

## 七、测试验证

1. `pnpm dev` 启动开发服务器
2. 登录后，在 Home 页面操作栏看到"回收站"按钮
3. 点击 → Drawer 打开，显示回收站列表
4. 删除一个文件 → 回收站中出现该文件

6. 关键词搜索：输入文件名 → 过滤结果
7. 分页切换：切换页码/每页数量
8. 单项还原（canRestore=true）→ 点击还原下拉 → "还原到原目录" → 文件恢复到原目录

14. 批量还原（含 canRestore=false）→ 弹出文件夹选择器
15. 批量彻底删除 → 确认弹窗 → 全部删除
16. 清空回收站 → 确认弹窗 → 全部清除
17. 恢复后验证 Home 文件列表和侧边栏树自动刷新
