# 2026-05-16 以来前端对接说明

## 一、对接范围

本文档面向前端，整理 2026-05-16 之后后端新增或行为变更的接口。重点是文件树拖拽排序、跨层移动、逻辑删除、批量删除和回收站。

统一响应结构：

```json
{
  "code": 200,
  "message": "",
  "data": {}
}
```

常见状态码：

- `200`：成功。
- `400`：参数错误或业务校验失败，例如资源不存在、同名冲突、非法类型。
- `403`：权限不足，例如普通用户尝试恢复到根目录或无目标目录编辑权限。
- `500`：未被明确捕获的运行时异常。

资源类型 `status` 约定：

| status | 类型 |
| --- | --- |
| `1` | 文本 `text` |
| `2` | 文件夹 `folder` |
| `3` | Excel |
| `4` | 普通文件 `file` |

## 二、文件树和主页列表

### 1. 获取主页列表

```http
POST /home/get
Content-Type: application/json
```

请求体：

```json
{
  "id": 12,
  "keyword": "合同",
  "sortBy": "sortOrder",
  "sortOrder": "asc"
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 否 | 当前文件夹 ID；`null` 表示根目录。 |
| `keyword` | 否 | 名称搜索关键字，后端会 trim，空字符串按无关键字处理。 |
| `sortBy` | 否 | `sortOrder`、`name` 或其他值；默认走 `sortOrder`。 |
| `sortOrder` | 否 | `asc` 或 `desc`，默认 `desc`。对 `sortOrder` 模式影响不大。 |

返回列表项新增/重点字段：

```json
{
  "id": 1,
  "name": "项目资料",
  "status": 2,
  "createTime": "2026-05-19T10:00:00",
  "updateTime": "2026-05-19T10:30:00",
  "owner": "zhuba",
  "folderId": null,
  "sortOrder": 0,
  "hasPermission": true,
  "permissionType": "EDIT",
  "pinned": false
}
```

前端注意：

- 列表只返回当前用户有权限看到的节点。
- 普通上传文件会过滤 Markdown 图片；Markdown 图片不作为普通文件树节点展示。
- 后端默认排序逻辑是：置顶优先，然后 `sortOrder`，最后 `updateTime` 兜底。

### 2. 获取完整文件树

```http
GET /home/tree
```

返回结构：

```json
{
  "code": 200,
  "message": "",
  "data": {
    "list": [
      {
        "id": 1,
        "name": "项目资料",
        "parentId": null,
        "folderId": null,
        "status": 2,
        "sortOrder": 0,
        "pinned": false,
        "hasPermission": true,
        "permissionType": "EDIT",
        "children": []
      }
    ]
  }
}
```

前端注意：

- 文件夹节点使用 `parentId`。
- 文本、Excel、文件节点通常使用 `folderId` 表示所在文件夹。
- `children` 始终按权限过滤后返回，普通用户看不到无权限节点。
- 展示拖拽树时建议统一使用 `{ id, status }` 作为节点唯一键，避免不同表 ID 重复。

## 三、拖拽排序

### 同级排序接口

```http
PUT /home/sort
Content-Type: application/json
```

请求体：

```json
{
  "parentFolderId": 12,
  "orderedIds": [
    { "id": 3, "status": 2 },
    { "id": 9, "status": 4 },
    { "id": 5, "status": 1 }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `parentFolderId` | 否 | 当前同级列表所属父文件夹；`null` 表示根目录。 |
| `orderedIds` | 是 | 拖拽后的同级节点顺序。每项必须有 `id` 和 `status`。 |

对接建议：

- 拖拽结束后，传当前父级下的完整同级顺序，不建议只传被拖动节点。
- `orderedIds` 内不能重复。
- 每个节点必须确实属于 `parentFolderId`，否则后端返回 `400`。
- 目标父级需要 `EDIT` 权限；根目录排序需要超级管理员权限。

成功返回：

```json
{
  "code": 200,
  "message": "",
  "data": null
}
```

## 四、跨层移动

### 移动文件树节点

```http
PUT /home/move
Content-Type: application/json
```

请求体：

```json
{
  "itemId": 9,
  "itemStatus": 4,
  "targetFolderId": 12
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `itemId` | 是 | 被移动资源 ID。 |
| `itemStatus` | 是 | 被移动资源类型：`1/2/3/4`。 |
| `targetFolderId` | 否 | 目标文件夹 ID；`null` 表示移动到根目录。 |

后端校验：

- 被移动节点必须存在且未删除。
- 源父级和目标父级都需要 `EDIT` 权限。
- 移动文件夹时，还需要该文件夹自身 `EDIT` 权限。
- 文件夹不能移动到自己或自己的子文件夹。
- 移动到根目录需要超级管理员权限。

前端建议：

- 拖拽到文件夹外或根层时，明确传 `targetFolderId: null`。
- 移动成功后重新拉取 `/home/tree` 或当前父级 `/home/get`，让 `sortOrder` 与权限状态以服务端为准。
- 如果收到 `403`，优先提示“无目标目录编辑权限”或“无根目录操作权限”。

## 五、删除接口行为变化

### 1. 单文件删除

```http
DELETE /minio/delete/{id}
```

行为变化：

- 现在是逻辑删除，不会立即删除 MinIO 对象。
- 成功后资源会从普通列表和文件树消失，并进入回收站。

### 2. 批量文件删除

```DELETE /home/delete/batch
Content-Type: application/json
{
  "items": [
    { "id": 1, "status": 1 },
    { "id": 2, "status": 2 },
    { "id": 3, "status": 3 },
    { "id": 4, "status": 4 }
  ]
}
status 仍然是：1=text、2=folder、3=excel、4=file。

```



### 3. 其他删除

这些已有接口现在也会进入逻辑删除流程：

| 接口 | 说明 |
| --- | --- |
| `DELETE /folder/delete/{id}` | 逻辑删除文件夹，并递归逻辑删除子文件夹、文本、Excel、文件。 |
| `DELETE /text/delete/{textId}` | 逻辑删除文本。 |
| `DELETE /excel/delete/{id}` | 逻辑删除 Excel。 |

前端删除成功后不要再认为数据已物理消失，应将其视为“移入回收站”。

## 六、回收站接口

### 1. 回收站列表

```http
GET /recycle-bin/list?current=1&pageSize=20&type=4&keyword=合同
```

查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `current` | 否 | 页码，默认 `1`。小于等于 0 时后端按 `1` 处理。 |
| `pageSize` | 否 | 每页数量，默认 `20`，最大 `100`。 |
| `type` | 否 | 资源类型：`1/2/3/4`。不传表示全部类型。 |
| `keyword` | 否 | 按资源名称模糊搜索。 |

返回示例：

```json
{
  "code": 200,
  "message": "",
  "data": {
    "current": 1,
    "pageSize": 20,
    "total": 3,
    "count": 3,
    "records": [
      {
        "id": 9,
        "status": 4,
        "typeName": "文件",
        "name": "合同.pdf",
        "parentFolderId": 12,
        "originalPath": "项目资料/合同.pdf",
        "owner": "zhuba",
        "deletedBy": "zhuba",
        "deletedAt": "2026-05-19 13:00:00",
        "deleteBatchId": "uuid",
        "updateTime": "2026-05-19 13:00:00",
        "canRestore": true,
        "canPurge": true
      }
    ]
  }
}
```

字段说明：

- `originalPath`：后端根据原父目录拼出的展示路径。
- `canRestore`：是否可恢复到原目录。
- `canPurge`：是否可彻底删除。
- 如果 `canRestore=false`，仍可以让用户选择一个新的目标文件夹后恢复。

### 2. 恢复资源

```http
POST /recycle-bin/restore
Content-Type: application/json
```

请求体：

```json
{
  "items": [
    { "id": 9, "status": 4 }
  ],
  "targetFolderId": 12,
  "renameOnConflict": true
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `items` | 是 | 要恢复的资源列表，每项由 `id + status` 定位。 |
| `targetFolderId` | 否 | 不传或 `null` 表示恢复到原目录；传值表示恢复到指定文件夹。 |
| `renameOnConflict` | 否 | 目标目录已有同名资源时是否自动重命名。 |

恢复规则：

- 如果恢复到原目录，但原目录不存在或也在回收站中，后端返回 `400`，前端应引导用户选择新目录。
- 恢复到根目录需要超级管理员权限。
- 恢复到普通文件夹需要目标文件夹 `EDIT` 权限。
- `renameOnConflict=false` 或不传时，同名冲突会返回 `400`。
- `renameOnConflict=true` 时，后端会自动追加类似“（恢复）”的后缀。
- 恢复文件夹时，会按删除批次同步恢复该文件夹树下同批删除的文本、Excel 和文件。

成功返回：

```json
{
  "code": 200,
  "message": "",
  "data": 1
}
```

`data` 是实际恢复的记录数；恢复文件夹时可能大于 `items.length`。

### 3. 彻底删除

```http
DELETE /recycle-bin/purge
Content-Type: application/json
```

请求体：

```json
{
  "items": [
    { "id": 9, "status": 4 }
  ]
}
```

说明：

- 彻底删除后数据库记录会被删除。
- 普通文件彻底删除时，会同步删除 MinIO 对象。
- 彻底删除文件夹时，会递归删除其下已删除的子文件夹、文本、Excel、文件，并清理相关文件对象。
- 普通用户需要满足以下任一条件：自己删除的资源，或对原父目录有 `EDIT` 权限；超级管理员不受此限制。
- 前端调用前必须做二次确认。

成功返回：

```json
{
  "code": 200,
  "message": "",
  "data": 1
}
```

## 七、推荐前端交互

### 文件树拖拽

- 同父级排序：调用 `/home/sort`。
- 跨父级移动：调用 `/home/move`，成功后重新刷新源目录和目标目录。
- 用 `id + status` 作为节点唯一 key。
- 不允许拖到自身或子孙节点，这个可以前端先禁用，后端也会校验。

### 删除

- 删除按钮文案建议改成“移入回收站”。
- 批量删除前显示选中数量。
- 删除成功后从当前列表移除，并提示“已移入回收站”。

### 回收站

- 列表页提供类型筛选、关键词搜索、分页。
- 恢复按钮根据 `canRestore` 控制：
  - `true`：可直接恢复到原目录。
  - `false`：引导用户选择目标文件夹。
- 彻底删除按钮根据 `canPurge` 控制，点击后必须二次确认。
- `DELETE /recycle-bin/purge` 是带 body 的 DELETE 请求，请确认封装层没有丢弃请求体。

## 八、联调检查清单

- 拖拽同级排序后刷新页面，顺序仍保持。
- 跨层移动普通文件、文本、Excel、文件夹都能正常移动。
- 普通用户尝试移动到根目录，应返回 `403` 或前端直接禁用。
- 删除文件后不再出现在 `/home/get`、`/home/tree`，但出现在 `/recycle-bin/list`。
- 删除文件夹后，回收站只展示顶层已删除文件夹；恢复该文件夹时，同批次子内容一起恢复。
- 恢复到原目录、恢复到指定目录、同名冲突自动重命名都要覆盖。
- 彻底删除文件后，回收站消失，MinIO 对象也应被清理。
