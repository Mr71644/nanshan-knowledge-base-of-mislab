# 回收站接口文档

## 一、通用说明

### 1. 权限规则

回收站接口仅允许管理员或超级管理员访问。

普通用户即使满足以下条件，也不能操作回收站：

- 是该资源的删除人。
- 对资源原父目录有 `EDIT` 权限。

前端应先调用 `GET /user/is-admin` 判断是否展示回收站入口。后端仍会在每个回收站接口做权限校验。

### 2. 统一响应结构

```json
{
  "code": 200,
  "message": "",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | number | 业务状态码，与 HTTP 状态码保持一致。 |
| `message` | string | 错误信息。成功时通常为空字符串。 |
| `data` | any | 响应数据。失败时为 `null`。 |

### 3. 资源类型 status

| status | 类型 |
| --- | --- |
| `1` | 文本 |
| `2` | 文件夹 |
| `3` | Excel |
| `4` | 文件 |

### 4. 常见错误码

| code | 场景 |
| --- | --- |
| `400` | 参数错误、资源不存在、目标目录不存在、同名冲突等业务校验失败。 |
| `403` | 当前用户不是管理员或超级管理员。 |
| `500` | 服务端运行异常。 |

权限不足响应示例：

```json
{
  "code": 403,
  "message": "只有管理员可以操作回收站",
  "data": null
}
```

## 二、判断当前用户是否管理员

### 接口信息

```http
GET /user/is-admin
```

### 请求参数

无。

### 响应 data

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `isAdministrator` | boolean | 是否为管理员或超级管理员。 |
| `username` | string | 用户名。 |
| `email` | string | 邮箱。 |
| `roleName` | string[] | 角色名称列表。 |

### 响应示例

```json
{
  "code": 200,
  "message": "",
  "data": {
    "isAdministrator": true,
    "username": "admin",
    "email": "admin@example.com",
    "roleName": ["管理员"]
  }
}
```

### 前端使用

- `data.isAdministrator === true`：展示回收站入口和操作按钮。
- `data.isAdministrator !== true`：隐藏回收站入口和操作按钮。

## 三、查询回收站列表

### 接口信息

```http
GET /recycle-bin/list
```

### 权限

仅管理员或超级管理员。

### Query 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `current` | number | 否 | `1` | 当前页码。小于等于 `0` 时后端按 `1` 处理。 |
| `pageSize` | number | 否 | `20` | 每页数量。最大 `100`。 |
| `type` | number | 否 | 无 | 资源类型：`1/2/3/4`。不传表示全部类型。 |
| `keyword` | string | 否 | 无 | 按资源名称模糊搜索。 |

### 请求示例

```http
GET /recycle-bin/list?current=1&pageSize=20&type=4&keyword=合同
```

### 响应 data

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `current` | number | 当前页码。 |
| `pageSize` | number | 每页数量。 |
| `total` | number | 总记录数。 |
| `count` | number | 当前页记录数。 |
| `records` | RecycleBinItem[] | 回收站资源列表。 |

### RecycleBinItem

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | number | 资源 ID。 |
| `status` | number | 资源类型：`1` 文本、`2` 文件夹、`3` Excel、`4` 文件。 |
| `typeName` | string | 类型名称。 |
| `name` | string | 资源名称。 |
| `parentFolderId` | number/null | 原父文件夹 ID。根目录资源为 `null`。 |
| `originalPath` | string | 原始路径展示值。 |
| `owner` | string | 资源所有者。 |
| `deletedBy` | string | 删除人。 |
| `deletedAt` | string | 删除时间。 |
| `deleteBatchId` | string | 删除批次 ID。 |
| `updateTime` | string | 更新时间。 |
| `canRestore` | boolean | 是否可恢复。管理员场景下一般为 `true`。 |
| `canPurge` | boolean | 是否可彻底删除。管理员场景下一般为 `true`。 |

### 响应示例

```json
{
  "code": 200,
  "message": "",
  "data": {
    "current": 1,
    "pageSize": 20,
    "total": 1,
    "count": 1,
    "records": [
      {
        "id": 9,
        "status": 4,
        "typeName": "文件",
        "name": "合同.pdf",
        "parentFolderId": 12,
        "originalPath": "项目资料/合同.pdf",
        "owner": "zhuba",
        "deletedBy": "zhuba",
        "deletedAt": "2026-05-19 13:00:00",
        "deleteBatchId": "uuid",
        "updateTime": "2026-05-19 13:00:00",
        "canRestore": true,
        "canPurge": true
      }
    ]
  }
}
```

## 四、恢复回收站资源

### 接口信息

```http
POST /recycle-bin/restore
Content-Type: application/json
```

### 权限

仅管理员或超级管理员。

### 请求 Body

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `items` | RecycleBinItemRef[] | 是 | 要恢复的资源列表。不能为空。 |
| `targetFolderId` | number/null | 否 | 恢复目标文件夹 ID。不传或 `null` 表示恢复到原目录。 |
| `renameOnConflict` | boolean | 否 | 目标目录存在同名资源时是否自动重命名。默认按 `false` 处理。 |

### RecycleBinItemRef

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | number | 是 | 资源 ID。 |
| `status` | number | 是 | 资源类型：`1/2/3/4`。 |

### 请求示例

```json
{
  "items": [
    { "id": 9, "status": 4 }
  ],
  "targetFolderId": 12,
  "renameOnConflict": true
}
```

### 业务规则

- `items` 会按 `status + id` 去重。
- `targetFolderId` 不传时，后端尝试恢复到资源原目录。
- 原目录不存在或也在回收站中时，返回 `400`。
- 指定 `targetFolderId` 时，目标文件夹必须存在且未删除，否则返回 `400`。
- 同名冲突时：
  - `renameOnConflict=false` 或不传：返回 `400`。
  - `renameOnConflict=true`：后端自动追加“（恢复）”后缀。
- 恢复文件夹时，会按删除批次同步恢复该文件夹树下同批删除的文本、Excel 和文件。

### 成功响应

```json
{
  "code": 200,
  "message": "",
  "data": 1
}
```

`data` 表示实际恢复记录数。恢复文件夹时，实际恢复数量可能大于 `items.length`。

### 错误响应示例

```json
{
  "code": 400,
  "message": "目标目录已存在同名资源：合同.pdf",
  "data": null
}
```

## 五、彻底删除回收站资源

### 接口信息

```http
DELETE /recycle-bin/purge
Content-Type: application/json
```

### 权限

仅管理员或超级管理员。

### 请求 Body

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `items` | RecycleBinItemRef[] | 是 | 要彻底删除的资源列表。不能为空。 |

### 请求示例

```json
{
  "items": [
    { "id": 9, "status": 4 }
  ]
}
```

### 业务规则

- 彻底删除不可恢复，前端调用前必须二次确认。
- 普通文件彻底删除时，会同步删除 MinIO 对象。
- 文件夹彻底删除时，会递归删除其下已删除的子文件夹、文本、Excel、文件，并清理相关 MinIO 对象。
- `DELETE /recycle-bin/purge` 需要携带 JSON body，前端请求封装不能丢弃 body。

### 成功响应

```json
{
  "code": 200,
  "message": "",
  "data": 1
}
```

`data` 表示实际彻底删除记录数。

## 六、前端联调检查

- 管理员可以打开回收站列表。
- 普通用户调用 `/recycle-bin/list` 返回 `403`。
- 普通用户看不到回收站菜单、恢复按钮、彻底删除按钮。
- 管理员可以恢复普通用户删除的资源。
- 管理员可以彻底删除任意回收站资源。
- 恢复同名冲突时，`renameOnConflict=true` 可以自动重命名。
- 彻底删除接口的 DELETE 请求 body 能正常传到后端。
