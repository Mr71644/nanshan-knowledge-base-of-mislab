**日期：** 2026-07-10 | **分支：** `test/migration-feasibility` | **结果：** ⚠️ 2/8 纯通过 + 6 环境限制

---

## 测试目标

验证 `Editor.create`（离屏 DOM）对**真实后端文档**的 Markdown→JSON 转换无损性：节点的结构完

整性、图片引用的保留、文本内容的完整性。

## 方法

1. 通过 `GET /text/get/{id}` 拉取 8 个真实文档（覆盖图片、表格、纯文本）
2. `new Editor({ element: detachedDiv, extensions, content: md, contentType: 'markdown' })`
3. `editor.getJSON()` → `editor.destroy()`
4. 逐文档检查：图片节点数、表格数、标题数、minio: 引用保留、文本内容

## 环境

同测试 1。注意测试环境**未加载自定义扩展**（MinioImage、CodeBlockWithToolbar），StarterKit 禁用了内置 codeBlock。

## 图片丢失分析

6 个含图片的文档转换后 `image` 节点数为 0。原因：

文档中的图片使用 `<img src="minio:xxx">` HTML 标签格式存储（由 MinioImage 的 `renderMarkdown()` 序列化产生），而非标准 `![alt](minio:xxx)` Markdown 语法。测试环境未加载 MinioImage 扩展，标准 Markdown 解析器将 `<img>` 视为 HTML 而非图片节点。

**这在生产环境中不是问题**——迁移引擎加载完整的 MinioImage 扩展后，无论 `![alt](minio:xxx)` 还是 `<img src="minio:xxx">` 都能正确解析为 image 节点。测试 1 已验证 `minio:` 作为 `attrs.src` 值可被 Editor.create 正确保留。

## 体积比

| 文档规模 | 体积比 | 说明 |
|----------|--------|------|
| 小文档（<100 字符） | 1.5x ~ 3.7x | JSON 固定开销占比大 |
| 大文档（14KB） | 6.1x | 表格密集时膨胀较大 |
| 总体 | 6.0x | 受表格文档影响 |

14KB MD → 88KB JSON 的 6.1x 比例在表格场景属正常范围（每个单元格产生独立的 paragraph+text 节点）。100 个此类文档总体积约 8.8MB，在 HTTP 可接受范围内。

## 结论

1. **纯文本和表格文档转换完全正确**（id=75, 80）
2. **图片丢失是测试环境限制**，非引擎问题。→ **已补充验证（`docs/test-retest-results.md`）：** 4/4 图片格式全覆盖通过，MD语法+HTML标签两种均正确解析
3. **体积膨胀可控**，最坏场景 6x，平均 ~4x
