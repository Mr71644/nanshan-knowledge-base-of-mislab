# 文件树拖拽排序功能 — 后端设计文档

## 一、需求背景

前端将实现文件树的拖拽排序功能。当用户通过拖拽调整同级节点的顺序后，前端会调用排序接口将新顺序持久化到数据库。后端需要：

1. 新增排序接口 `PUT /home/sort`
2. 数据库相关表添加 `sort_order` 字段
3. 现有的树查询接口按 `sort_order` 排序返回

## 二、数据库变更

### 2.1 新增字段

以下所有表均需添加 `sort_order` 整型字段：

| 表名 | 说明 |
|------|------|
| 文件夹表 | `status = 2` |
| 文档表 | `status = 1` |
| Excel 表 | `status = 3` |
| 普通文件表 | `status = 4` |

字段定义：

```sql
ALTER TABLE <表名> ADD COLUMN sort_order INT NOT NULL DEFAULT 0;
```

### 2.2 数据迁移

已有的数据 `sort_order` 默认为 0，保持原有排序行为（按 `update_time DESC`）。可选择性执行一次性迁移脚本，将现有数据按 `update_time DESC` 顺序赋予递增的 `sort_order` 值。

### 2.3 排序规则

- 同一父级下的兄弟节点按 `sort_order ASC` 排序
- 置顶（`pinned = true`）的节点排在最前面，不受 `sort_order` 影响
- 完整排序逻辑：`ORDER BY pinned DESC, sort_order ASC`

## 三、新增接口

### 3.1 排序接口

```
PUT /home/sort
Content-Type: application/json
Authorization: Bearer <token>
```

**请求体：**

```json
{
  "parentFolderId": null,
  "orderedIds": [
    { "id": 12, "status": 2 },
    { "id": 5,  "status": 1 },
    { "id": 8,  "status": 3 },
    { "id": 14, "status": 4 }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `parentFolderId` | `number \| null` | 父文件夹 ID，`null` 表示根目录 |
| `orderedIds` | `Array<{id, status}>` | 按新顺序排列的兄弟节点列表 |

**响应：**

```json
{
  "code": 200,
  "message": "success"
}
```

**后端处理逻辑：**

1. 校验用户权限（对该父级文件夹有编辑权限）
2. 遍历 `orderedIds`，根据每项的 `status` 确定对应的数据表：
   - `status = 1` → 文档表
   - `status = 2` → 文件夹表
   - `status = 3` → Excel 表
   - `status = 4` → 普通文件表
3. 对每项执行：`UPDATE <对应表> SET sort_order = <索引> WHERE id = <id>`
4. 返回成功响应

**伪代码：**

```java
for (int i = 0; i < orderedIds.size(); i++) {
    OrderedItem item = orderedIds.get(i);
    String table = getTableByStatus(item.getStatus());
    // table: 1→text, 2→folder, 3→excel, 4→minio_file
    jdbcTemplate.update(
        "UPDATE " + table + " SET sort_order = ? WHERE id = ?",
        i, item.getId()
    );
}
```

**错误响应：**

| HTTP 状态码 | 场景 |
|-------------|------|
| 401 | 未登录 / token 过期 |
| 403 | 无编辑权限 |
| 400 | `orderedIds` 为空、`id` 不存在、`status` 无效 |

## 四、现有接口变更

### 4.1 `GET /home/tree`（获取文件树）

**变更内容：** 查询时增加排序条件

```sql
-- 之前：
SELECT * FROM ... WHERE parent_id = ? ORDER BY update_time DESC

-- 之后：
SELECT * FROM ... WHERE parent_id = ? ORDER BY pinned DESC, sort_order ASC, update_time DESC
```

说明：
- `pinned DESC` — 置顶项优先
- `sort_order ASC` — 按自定义排序
- `update_time DESC` — 作为兜底排序（当 `sort_order` 相同时）

### 4.2 新增内容的默认 `sort_order`

以下接口在创建新记录时，需将 `sort_order` 设为**同级最大值 + 1**：

| 接口 | 说明 |
|------|------|
| `POST /folder/add` | 新建文件夹 |
| `POST /text/add` | 新建文档 |
| `POST /excel/upload` | 上传 Excel |
| `POST /minio/upload` | 上传文件 |
| `POST /minio/upload/batch` | 批量上传文件 |

```sql
-- 获取同级最大 sort_order
SELECT COALESCE(MAX(sort_order), -1) FROM <表> WHERE parent_id = ?

-- 新记录的 sort_order = 上面的结果 + 1
INSERT INTO <表> (..., sort_order) VALUES (..., <max_sort_order + 1>)
```

这样新建的项会出现在同级最后面，不影响已有的排序。

### 4.3 `POST /home/get`（获取文件夹内容列表）

同样需要增加排序：

```sql
SELECT * FROM ... WHERE folder_id = ? ORDER BY pinned DESC, sort_order ASC, update_time DESC
```

### 4.4 `POST /home/pin/toggle`（置顶/取消置顶）

无需变更。置顶逻辑独立于排序逻辑。

## 五、接口汇总

| 接口 | 类型 | 说明 |
|------|------|------|
| `PUT /home/sort` | **新增** | 排序同级节点 |
| `GET /home/tree` | **变更** | 添加 `sort_order` 排序 |
| `POST /home/get` | **变更** | 添加 `sort_order` 排序 |
| `POST /folder/add` | **变更** | 创建时设置 `sort_order` |
| `POST /text/add` | **变更** | 创建时设置 `sort_order` |
| `POST /excel/upload` | **变更** | 创建时设置 `sort_order` |
| `POST /minio/upload` | **变更** | 创建时设置 `sort_order` |
| `POST /minio/upload/batch` | **变更** | 创建时设置 `sort_order` |

## 六、注意事项

1. **事务处理**：`PUT /home/sort` 中的多次 UPDATE 应在同一个事务中执行，保证原子性
2. **权限校验**：排序操作需校验用户对目标父级文件夹有编辑权限
3. **`orderedIds` 完整性**：建议校验传入的 `orderedIds` 包含该父级下的所有子项（可选，增强一致性）
4. **向后兼容**：`sort_order` 默认值为 0，旧数据无需迁移即可正常工作（都为 0 时按 `update_time` 降序）
