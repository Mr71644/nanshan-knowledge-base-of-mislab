# 文件夹与文件重命名修复文档

## 背景

本次排查针对文件和文件夹重命名功能。问题集中在统一重命名接口、文件夹重命名后的文件 URL 同步、Markdown 图片路径同步，以及根目录文件重命名等场景。

涉及接口：

- `POST /minio/rename`
- `PUT /folder/update`

涉及文件：

- `src/main/java/wiki/record/application/service/impl/MinioServiceImpl.java`
- `src/main/java/wiki/record/application/service/impl/FolderServiceImpl.java`
- `src/main/resources/mapper/FileMapper.xml`
- `src/test/java/wiki/record/application/service/impl/MinioServiceImplTest.java`
- `src/test/java/wiki/record/application/dao/FileMapperXmlTest.java`

## 问题表现

1. `/minio/rename` 的 DTO 和接口说明表示支持文件与文件夹重命名，但实际传入 `type=2` 文件夹时会直接抛错，要求调用 `/folder/update`。
2. 前端如果统一使用 `/minio/rename`，文件可以重命名，文件夹会失败。
3. 文件夹重命名后，数据库中的文件 URL 通过旧路径前缀批量替换，可能误匹配其他同名前缀目录。例如重命名 `A` 时，`A1/file.pdf` 也可能被错误匹配。
4. Markdown 图片原本会被排除在文件夹重命名的 MinIO 对象迁移列表之外，可能出现数据库 URL 已更新但 MinIO 实际对象仍在旧路径的情况。
5. 根目录文件重命名时，SQL 条件 `folder_id = #{folderId}` 无法匹配 `NULL`，导致数据库记录不更新。

## 根因

### 1. 接口契约与实现不一致

`RenameFileDTO` 的注释和 `MinioService` 的接口说明都写明统一重命名接口支持文件和文件夹，但 `MinioServiceImpl.renameFile` 对 `type=2` 的处理是直接拒绝。

### 2. URL 前缀匹配边界不严

原 SQL 使用：

```sql
WHERE url LIKE CONCAT(#{oldPathPrefix}, '%')
```

这会把同样以旧路径字符串开头的其他目录也匹配进来，缺少目录边界判断。

### 3. Markdown 图片路径处理不完整

文件夹重命名时，查询待迁移文件的 SQL 排除了 `/markdown-images/`。但 Markdown 图片也在文件夹路径下，文件夹改名后也需要同步移动 MinIO 对象和更新 URL。

### 4. NULL 条件使用错误

SQL 中 `folder_id = NULL` 永远不成立，根目录文件应使用 `folder_id IS NULL`。

## 修复方案

### 1. 统一重命名接口支持文件夹

`MinioServiceImpl.renameFile` 对 `type=2` 时不再抛错，而是委托 `FolderService.updateFolder`：

```java
folderService.updateFolder(new FolderUpdateDTO(id, newName));
```

这样 `/minio/rename` 和 `/folder/update` 对文件夹重命名保持一致行为，也避免前端需要为同一个重命名动作拆两套接口逻辑。

同时增加参数校验：

- DTO 不能为空
- `id` 不能为空
- `newName` 不能为空
- 自动识别类型时，如果文件表和文件夹表出现相同 ID，要求显式传入 `type`

### 2. 收紧文件夹 URL 批量更新边界

将批量更新条件从宽泛前缀匹配改为：

```sql
WHERE url = #{oldPathPrefix}
   OR LEFT(url, CHAR_LENGTH(#{oldPathPrefix}) + 1) = CONCAT(#{oldPathPrefix}, '/')
```

只有完整路径本身，或旧路径后紧跟 `/` 的子路径会被匹配，避免 `A` 误匹配 `A1`。

URL 替换方式也改为基于前缀长度拼接：

```sql
SET url = CONCAT(#{newPathPrefix}, SUBSTRING(url, CHAR_LENGTH(#{oldPathPrefix}) + 1))
```

避免 `REPLACE` 替换 URL 中其他位置的相同字符串。

### 3. 文件夹重命名时同步 Markdown 图片

`findFilesByUrlPrefix` 不再排除 `/markdown-images/`，确保文件夹下的 Markdown 图片也会进入路径迁移流程。

### 4. 修复根目录文件重命名

`updateFileNameAndUrl` 根据 `folderId` 是否为空选择不同 SQL 条件：

```xml
<choose>
    <when test="folderId == null">
        AND folder_id IS NULL
    </when>
    <otherwise>
        AND folder_id = #{folderId}
    </otherwise>
</choose>
```

## 影响范围

### 正向影响

- 前端可以继续使用统一重命名接口 `/minio/rename` 处理文件和文件夹。
- 文件夹重命名后，普通文件和 Markdown 图片路径同步更完整。
- 避免同名前缀目录被误更新。
- 根目录文件重命名可以正确更新数据库。

### 兼容性

- `/folder/update` 仍然可用。
- `/minio/rename` 对文件重命名保持原有行为。
- `/minio/rename` 新增支持 `type=2` 文件夹重命名。

## 建议

1. 前端重命名时建议显式传入 `type`，避免文件和文件夹 ID 重叠时无法自动判断。
2. 后续如果继续扩展 `type=1 text` 或 `type=3 excel` 的统一重命名能力，应补充对应 Service 委托和回归测试。
3. 若生产环境已有被误改的 URL，需要结合操作日志或数据库备份单独修复历史数据。
